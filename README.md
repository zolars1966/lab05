### Задание 1

Возьмём числа 3/32 и 1/10.

**1. Число 3/32.** Знаменатель равен 32 = 2⁵, поэтому дробь имеет конечную двоичную запись. Умножаем дробную часть на 2 и каждый раз выписываем целую часть:

- 3/32 * 2 = 3/16 -> 0;
- 3/16 * 2 = 3/8 -> 0;
- 3/8 * 2 = 3/4 -> 0;
- 3/4 * 2 = 1,5 -> 1;
- оставшаяся дробная часть 0,5: 0,5 * 2 = 1,0 -> 1.

Получаем: **3/32 = 0,00011₂**.

**2. Число 1/10.** Повторяем умножение дробной части на 2, каждый раз записывая целую часть:

| Дробная часть до умножения | Удвоенная часть | Следующий бит |
|---:|---:|---:|
| 0,1 | 0,2 | 0 |
| 0,2 | 0,4 | 0 |
| 0,4 | 0,8 | 0 |
| 0,8 | 1,6 | 1 |
| 0,6 | 1,2 | 1 |
| 0,2 | 0,4 | 0 |
| 0,4 | 0,8 | 0 |
| 0,8 | 1,6 | 1 |

После появления остатка 0,2 процесс повторяется: остатки 0,2 -> 0,4 -> 0,8 -> 0,6 -> 0,2. Поэтому двоичная запись периодическая:

**1/10 = 0,0001(1001)₂**.

Здесь `1001` — период, а `0001` — непериодическая часть.

### Задание 2

**123,4**

Целая часть: 123 = 64 + 32 + 16 + 8 + 2 + 1, значит 123 = 1111011₂.

Дробная часть 0,4:

- 0,4 * 2 = 0,8 -> бит 0;
- 0,8 * 2 = 1,6 -> бит 1, остаток 0,6;
- 0,6 * 2 = 1,2 -> бит 1, остаток 0,2;
- 0,2 * 2 = 0,4 -> бит 0.

Остаток 0,4 повторился, значит дальше циклически повторяются биты `0110`. Получаем:

**123,4 = 1111011,011001100110...₂ = 1,1110110110011001100110011001100110011001100110011010...₂ * 2⁶**.

Для `double` отводится 1 бит знака, 11 бит порядка и 52 бита мантиссы. Число положительное, поэтому бит знака равен `0`. Смещение порядка равно 1023, сохранённый порядок: 6 + 1023 = 1029 = `(10000000101)₂`.

Первые 52 бита после ведущей единицы мантиссы с учётом округления:

`1110110110011001100110011001100110011001100110011010`

Итоговое представление `double`:

```
0 10000000101 1110110110011001100110011001100110011001100110011010
```

Дробь 0,4 имеет бесконечную двоичную запись, поэтому в `double` она хранится приближённо. Последний сохранённый бит учитывает округление до ближайшего представимого числа.

### Задание 4

В математике 99,99 / 10 + 0,001 равно 10. Но Python хранит `99.99` как ближайшее доступное двоичное число, а не как точную десятичную дробь. В результате промежуточное значение может оказаться чуть меньше 10. Функция `int()` отбрасывает дробную часть, поэтому получается 9.

Если требуется округление до ближайшего целого, следует использовать `round()`:

```python

```

### Задание 5

В Python `x = 1/3` хранится приближённо. Для `double`-подобного типа `float` это примерно:

`x = 0,3333333333333333148…`

Цикл сначала складывает `x` и `y`, а затем вычитает `y`. В точной арифметике результат всегда был бы равен `x`. В арифметике с плавающей точкой при большом `y` сумма `x + y` округляется до ближайшего представимого числа. Если `x` меньше половины шага между соседними числами около `y`, добавка `x` теряется, и `(x + y) - y` становится 0.

Для `double` расстояние между соседними числами порядка `y` примерно равно `y * 2⁻⁵²`. При `y = 10^k` это около `10^k * 2,22 * 10⁻¹⁶`. Пока этот шаг заметно меньше `1/3`, добавка обычно сохраняется; когда шаг становится сравним с `1/3`, результат начинает искажаться. Например, при `y = 10^15` шаг около 0,222, а при `y = 10^16` — около 2,22, поэтому `x` уже теряется при сложении.

Погрешность здесь определяется не только самим `x`, но и масштабом `y`: чем больше `y`, тем грубее сетка представимых чисел вокруг суммы. Из-за округления сложения последующее вычитание не может восстановить потерянные биты.

### Задание 8

Минимальное натуральное число, которое нельзя точно представить в `double`, — **2⁵³ + 1 = 9007199254740993**.

У `double` 53 значащих двоичных разряда с учётом неявной ведущей единицы. Все целые числа до 2⁵³ включительно представимы точно, но около 2⁵³ расстояние между соседними представимыми числами становится равным 2. Поэтому 9007199254740993 находится ровно между двумя доступными числами и округляется к одному из них (при стандартном округлении — к 9007199254740992).

Следующее целое после него, 9007199254740994, уже представимо точно: оно чётное и совпадает с соседним значением сетки `double`. Важно: в программе само число следует записывать как целочисленный литерал, а не как литерал с плавающей точкой, иначе округление может произойти ещё при разборе исходного кода.

### Задание 9

```python
import sys

def solve():
    data = sys.stdin.read().split()
    if not data:
        return

    t = int(data[0])
    results = []
    idx = 1

    for _ in range(t):
        p1 = int(data[idx]); q1 = int(data[idx + 1])
        p2 = int(data[idx + 2]); q2 = int(data[idx + 3])
        p3 = int(data[idx + 4]); q3 = int(data[idx + 5])
        p4 = int(data[idx + 6]); q4 = int(data[idx + 7])
        idx += 8

        if q1 < 0: p1, q1 = -p1, -q1
        if q2 < 0: p2, q2 = -p2, -q2
        if q3 < 0: p3, q3 = -p3, -q3
        if q4 < 0: p4, q4 = -p4, -q4

        numA = p1 * q2 + p2 * q1
        denA = q1 * q2

        numB = p3 * q4 + p4 * q3
        denB = q3 * q4

        left  = numA * denB
        right = numB * denA

        if left == right:
            results.append("0")
        elif left < right:
            results.append("-1")
        else:
            results.append("1")

    sys.stdout.write(" ".join(results) + "\n")

if __name__ == "__main__":
    solve()
```

### Дополнительное задание 2

Так как исходные числа записаны максимум с 10 знаками после точки, каждое из них кратно 10⁻¹⁰. Различие двух сумм, если они не равны, как минимум 10⁻¹⁰. Выберем `eps = 1e-12`: он меньше минимального возможного ненулевого разрыва и при этом с запасом для ошибки вычислений `double` для чисел такого масштаба (до 100).

```cpp
#include <iostream>
#include <cmath>

int main() {
    double a, b, c, d;
    std::cin >> a >> b >> c >> d;

    const double eps = 1e-12;
    double x = a + b;
    double y = c + d;

    if (x - y > eps) std::cout << 1;
    else if (y - x > eps) std::cout << -1;
    else std::cout << 0;

    return 0;
}
```

Здесь `1` означает, что `a+b` больше, `-1` — что `c+d` больше, `0` — что суммы равны с точностью `eps`.

### Дополнительное задание 3

Чтобы перевести вводимое число в двоичную систему без потерь и погрешности, принимаем ее как строку. Затем разбиваем на целую и дробные части и работаем с ними отдельно.

Код представляет дробную часть как обыкновенную дробь `f/d`, где `d = 10^k`. Затем в цикле 1000 раз умножает числитель `f` на 2 — целая часть результата (`f // d`) даёт очередной двоичный разряд, а остаток (`f % d`) остаётся для следующего шага. 

Целая часть числа просто переводится через `bin()`, а дробная — циклом.

```python
s = input()
if '.' in s:
    a, b = s.split('.')
else:
    a, b = s, ''

n = int(a) if a else 0
f = int(b) if b else 0
d = 10 ** len(b)

res = bin(n)[2:] + '.'
for _ in range(1000):
    f *= 2
    res += str(f // d)
    f %= d

print(res)
```

### Дополнительное задание 4

Обычная `acos(x)` определена только при `x` в диапазоне от −1 до 1. Функция `acos_e(x, ep)` учитывает погрешность вычислений:

- если `x` выходит за диапазон больше чем на `ep`, возвращает NaN (`0.0 / 0.0`), обозначая ошибочный аргумент;
- если `x` лишь немного больше 1 или меньше −1, считает это погрешностью округления и прижимает значение к ближайшей границе;
- затем вызывает обычную `acos(x)`.

Так можно избежать ошибки из-за результата вроде `1.0000000000000002`, который математически должен был быть равен 1. Значение `ep` должно соответствовать ожидаемой погрешности конкретных вычислений.

### Дополнительное задание 5

Векторное произведение в плоскости для векторов AB и AC:

`cross = (Bx - Ax) * (Cy - Ay) - (By - Ay) * (Cx - Ax)`.

- `cross > 0`: C находится слева от направленного вектора AB;
- `cross < 0`: C находится справа;
- `cross` близок к нулю: точки лежат на одной прямой с учётом допуска.

Координаты имеют не более 6 знаков после точки, поэтому различие ненулевых точных определителей кратно 10⁻¹². Выберем `eps = 1e-14`: он меньше этого шага, но покрывает обычную ошибку округления нескольких операций `double` при координатах меньше 10.

```cpp
#include <iostream>
#include <cmath>

int main() {
    double ax, ay, bx, by, cx, cy;

    std::cin >> ax >> ay >> bx >> by >> cx >> cy;

    double abx = bx - ax;
    double aby = by - ay;
    double acx = cx - ax;
    double acy = cy - ay;

    double cross = abx * acy - aby * acx;
    const double eps = 1e-14;

    if (cross > eps) std::cout << "слева";
    else if (cross < -eps) std::cout << "справа";
    else std::cout << "на прямой";

    return 0;
}
```
